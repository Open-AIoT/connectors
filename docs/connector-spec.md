## 1. 定位与分层

### 1.1 连接器是什么

连接器（connector）是三方 AI/协作平台与 Open AIoT 接入层（L1 MCP 绑定 + L2 安全）之间的适配服务：

```
平台用户 ──(平台消息/卡片)──▶ 连接器 ──(MCP tools/call, Bearer)──▶ Open AIoT 接入层 ──▶ 设备
```

连接器只做四件事（规划 P10，薄适配层）：**收平台消息、做身份映射、调 MCP、渲染结果**。业务逻辑、设备语义、授权判定一律下沉到接入层；连接器**不得**自行实现 scope 检查之外的越权放行，也不得复制上游已有的判定逻辑。

### 1.2 平台无关层 + 平台适配层（MUST）

连接器实现**必须**分为两层：

- **平台无关层（core）**：交互原语——入站消息（`InboundMessage`）、身份（`Identity`）、回复（`Reply`/`Card`）、确认（§5）、身份映射接口（§4）、意图解析接口（§1.3）。core **不得** import 任何平台 SDK。
- **平台适配层（adapter）**：每个平台一个适配器，负责事件验签/解密、原语翻译、原生组件渲染、回调应答。

检验方法：新增一个平台时 core 应当一行不改。适配层跟随平台改版独立演进，弃用走版本政策的弃用流程，不影响其他适配器。

### 1.3 意图解析是可插拔接口

连接器本身**不是** LLM 应用。用户文本 → 工具调用的意图识别由 `IntentParser` 接口抽象：

- 一期参考实现内置机械命令解析器（`CommandParser`），用于无模型的演示链路；
- 生产形态下，意图识别由平台侧 AI 能力（飞书智能伙伴等）或连接器接入的模型承担——实现同一接口，管线不变。

## 2. 接入形态与凭据边界

1. 连接器以 MCP 客户端身份消费接入层端点（当前为 `POST /mcp`，Streamable HTTP），凭据形态遵循 L2 规范的凭据代际（一期 G1 静态 Bearer）。
2. **凭据不出边界（MUST）**：连接器持有上游凭据；平台侧（消息、卡片、回调 value）**不得**携带上游凭据本体。平台侧只出现会话级、一次性的确认令牌（§5）。
3. **token 透传禁令**：平台用户的任何凭据**不得**原样转发给上游（L2 §6.2 confused deputy 反模式）；用户身份以声明形式进审计链（`chain.user`）。
4. 凭据**不得**出现在平台消息、卡片、日志、错误文本中（L2 §7.3）。

## 3. 配置模型

一份连接器配置 = 一个"平台租户 × 设备范围"的绑定。规范字段：

| 字段 | 含义 | 约束 |
|---|---|---|
| `mcp.endpoint` | 接入层 MCP 端点 | 必填 |
| `mcp.token` | 连接器持有的上游凭据 | 必填；配置文件不得进版本库（部署义务） |
| `identity.strategy` | 身份映射策略 | 必填，取值见 §4.2；一期 `shared` |
| `confirm.timeout` | 确认超时 | 必填/有缺省；超时默认拒绝（§5.3） |
| `confirm.tools` | 追加需确认的工具名单 | 可选；**只能收紧不得放宽**（与标注推导取并集） |
| `<platform>.*` | 平台适配层配置（App ID/Secret、Encrypt Key 等） | 各适配器自定 |

设备范围（device_scope）一期由上游凭据在接入层的 scope 决定，连接器不另设实例内动态越权；多设备范围部署多个实例。

## 4. 身份映射接口

### 4.1 接口语义

输入：平台用户标识、平台租户标识、会话上下文、连接器配置。
输出：一次 MCP 调用应使用的凭据（含审计注记），或**拒绝**（未映射用户）。
任何映射环节的异常**必须** fail-closed（L2 §4.5）。

### 4.2 三策略（逐期实现）

| 策略 | 语义 | 期 |
|---|---|---|
| `shared` 共享凭据 | 全体平台用户共用连接器凭据，用户身份仅进审计（`chain.user`）。对应 L2 §3.1 G1 的已知局限（凭据即平台），适用只读或小团队演示 | Phase 1–2 |
| `table` 管理员映射表 | 管理员预登记"平台用户 → 凭据/scope"；未登记用户拒绝 | Phase 2 |
| `oauth` 用户自助授权 | 平台用户经授权链接完成 OAuth 式自助授权，获得个人 scope 凭据（依赖 L2 G3 授权流） | Phase 3 |

1. 身份映射**必须**实现为可插拔模块接口，企业可替换为对接自有 IdP 的实现。
2. 无论策略，审计链 `chain.user` **必须**如实记录平台用户身份（L2 §8.1）。

## 5. 危险操作的平台侧确认

### 5.1 触发条件（MUST）

工具的 `readOnlyHint=false`（即 L0 安全分级经绑定层渲染的标注）即需确认；`confirm.tools` 配置可追加。**管理员可收紧、不得放宽**。确认绑定工具的安全分级而非单次调用表面（L2 §5.1）。

### 5.2 confirm 原语（平台无关层定义）

```
confirm(request_id, summary, params_digest, risk_level, timeout)
    → confirmed | rejected | expired
```

确认请求**必须**携带：request_id、一次性确认令牌、操作与目标摘要（双语文案）、参数快照、超时时间。

### 5.3 防重放与快照语义（MUST）

1. 确认令牌为一次性随机串，随卡片按钮 `value` 下发，回调时常数时间比较校验；
2. 请求被消费一次（无论确认/拒绝/超时/无效）即作废，重放一律 `invalid`；
3. **超时默认拒绝**：超过 `timeout` 未确认视为 `expired`，不执行；
4. 被执行的参数**必须**是登记时的快照；回调里携带的任何参数**必须**忽略（防回调侧改参）；
5. 确认结果（含确认人身份、层级）**必须**进审计链（L2 §5.3、§7.1 `chain.confirm`）。

### 5.4 降级与兜底（MUST）

- 平台支持原生交互组件（卡片按钮等）时用平台级确认（L2 §5.2 三层表达的第三层）；
- 平台不支持可靠确认的（纯对话式插件等），连接器**必须**拒绝需确认调用并返回引导性错误，**不得**静默降级为无确认执行；
- 模型/机器人在确认完成前**不得**向用户声称"已执行"。

## 6. 消息与结果渲染约定

1. 平台无关层定义回复形态：`Reply{ Text, Card? }`——`Text` 必有（降级兜底），`Card` 为平台无关卡片结构（标题 + 键值字段 + 动作按钮）。
2. 适配层把 `Card` 映射为平台组件；平台不支持时降级为 `Text`（降级规则在各适配器文档写明）。
3. 渲染文本面向平台用户，双语就绪；长结果分页沿用上游分页约定。
4. 控制类调用结果**必须**包含执行状态与生效参数回执。
5. 设备上报的自由文本属不可信数据（L2 §6.3）：渲染时**不得**让其进入按钮文案、标题等会被二次解析为指令的位置。

## 7. 错误呈现约定

错误分三类，文案模板统一（适配器不得自行发明）：

| 类别 | 例子 | 呈现 |
|---|---|---|
| 用户错误 | 越权、参数错、未映射 | 引导用户纠正/联系管理员 |
| 平台错误 | 回调超时、限流 | 提示稍后重试 |
| 接入层错误 | MCP problem JSON | 透传 code + 翻译为人话摘要 |

原始错误码**必须**保留在呈现文本中（排障与审计对账）；凭据、内部地址等敏感信息**不得**出现在平台消息里。

## 8. 审计

每次调用与确认产出一条 JSON 审计行，字段对齐 L2 §7.1：`chain.platform`、`chain.user`、`chain.session`、`operation`、`result`、`chain.confirm`（确认人、request_id）。凭据只出现策略注记，不落本体。

## 9. 新平台接入 checklist（一致性验收）

一个新平台适配器合入前**必须**逐项通过：

1. 事件验签/解密通过，错误 token/签名 fail-closed；
2. 身份映射接口接入，未映射用户被拒绝且不触达上游；
3. 危险操作发起确认前**零调用**上游；确认后恰好执行一次（一次性令牌）；
4. 超时默认拒绝；重放无效；
5. 回复渲染：有卡片用原生组件，降级文本可读；
6. 三类错误按 §7 呈现，敏感信息不泄露；
7. 审计行字段齐 §8。

目标成本：熟悉该平台开放平台的中级工程师 5–10 人日完成适配并通过本 checklist（子规划 04 §5.5）。

## 10. 一期已知取舍（非规范性）

- 确认存内存，进程重启即失效（持久化属实现域）；
- 消息去重未实现（飞书重投可能重复回复；控制类由确认快照兜住，只读类重复无害）；
- 卡片确认后不做局部更新，以新消息 + toast 反馈；
- 回调同步处理（飞书 3 秒预算内）；慢速上游需改异步应答；
- 意图解析为机械命令解析器，非 LLM。
